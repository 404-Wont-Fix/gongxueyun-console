# 日历与自动排班

## 三个数据源

- 中国政府网：读取国务院办公厅年度放假通知，解析放假区间及调休上班日期。公告链接从 holiday-cn 的 `papers` 自动发现，并缓存；2026 年有官方链接作为首次发现的备用入口。
- holiday-cn：`https://raw.githubusercontent.com/NateScarlet/holiday-cn/master/{year}.json`。
- 提莫 API：`https://timor.tech/api/holiday/year/{year}`。

第三方接口不等于政府官方 API。三源按“日期 + 是否放假”核对，不要求节日名字一致（例如春节/初一）。来源、抓取结果、内容摘要 SHA256、最近检查时间和可信缓存时间都保存在本地。

启动后后台同步当年和下一年，每 24 小时重试；不阻塞网页启动。日历同步独立于自动打卡开关。测试环境禁用联网后台任务。管理员可以手动重试指定年份。

### 信任与故障策略

- 完整政府原文可解析，或两个结构化源完整且一致，才能接受年度数据。
- 任意成功解析的来源日期冲突，不覆盖旧可信数据，并显示冲突状态。
- 断网/限流/网页结构改变/新一年尚未公布：保留旧缓存；无旧缓存时不把未知日期当作工作日，暂停依赖官方日历的自动打卡。
- 三源都尝试使用，不伪造“全部正常”。下一年未公布不会回退使用本年日期。
- 政府网页不是稳定的结构化接口；无法安全解析时明确报错，不能保证任何未来版式都能自动解析。只剩单一第三方源时不初始化新年份。
- 网络请求限制域名、协议、重定向、超时、响应大小，不允许用户提供任意抓取 URL。

## 排班优先级

1. 账号单日自定义：正常上下班 / 休息卡 / 不自动打卡。
2. 开启“跟随中国法定放假与调休”时：官方整个放假区间每天一次 `HOLIDAY`（沿用上班时间）；调休补班日期正常 `START/END`。
3. 普通日期按账号执行星期。新账号默认七天均执行；已有账号保留原工作日选择。全不选沿用旧规则解释为每天。

自动打卡仍需账号启用且打开“自动打卡”。假日使用上班时间，独立于普通日的上班开关。调整单日安排不会立即补发过去时间的任务，也不会删除既有记录。延迟队列执行前重新检查当前日期、排班、账号开关与是否已有相反类型的执行，避免排班变化后发出过期任务。

已有当天休息卡成功/待确认/待验证的账号，自动调度不再发上下班；已有上下班的账号，自动调度不再发休息卡。手动提交仍由用户确认。报告自动任务仍沿用原报告星期逻辑，本次不改变报告发送规则。

## 日历统计口径

- 预计任务依据当前配置计算，属于预览，不是历史排班快照。
- 已确认按账号/日期/打卡类型去重，来源为本系统经回查确认的执行以及手动查询同步的工学云记录。
- 已提交但未确认、待验证、失败分开展示；登录检测、报告不计入打卡数量。
- 从工学云同步记录只做查询，不发起打卡。查询失败保留上次快照。
- 日历默认展示可见账号汇总，也可筛选单账号；普通用户不能查看或更改其他用户的账号。
- 记录为本地已知快照，不保证反映上游之后的撤销；可到考勤记录页再次核对。官方日历自动获取不意味着在打开日历时登录所有账号查询记录。
