# GongXueYun Console 部署与运维

## 1. 环境变量

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `APP_SECRET` | ✅ | — | ≥32 位随机串；签发 JWT + 加密账号密码。**变更后已保存的密码/会话失效** |
| `ADMIN_USERNAME` | ✅ | admin | 首次启动创建，已存在则不改 |
| `ADMIN_PASSWORD` | ✅ | admin12345 | 首次启动创建；请立即修改 |
| `APP_ENV` | | production | `development` 会放宽一些提示 |
| `DATABASE_URL` | | `sqlite:////data/gxy.db` | 也可 `mysql+pymysql://user:pass@host/db` |
| `SCHEDULER_ENABLED` | | true | 多副本部署时只在一个副本开启 |
| `SCHEDULER_TICK_SECONDS` | | 30 | 调度检查间隔 |
| `TASK_LOCK_SECONDS` | | 300 | 单账号写任务锁 |
| `GXY_PACKAGE_VERSION` | | 5.41.6 | 客户端版本 |
| `GXY_BUILD_NUMBER` | | 50291 | versionCode |
| `GXY_CODE_VERSION` | | 292 | 公共头 codeVersion |
| `CAPTCHA_MODEL_DIR` | | 空 | 放 `yolov5n.onnx` 与 `ocr.onnx` 后启用点选自动识别 |
| `MAP_TILE_URL` | | 高德栅格 | 底图模板，需含 `{x}{y}{z}`，可选 `{s}`；设置页可覆盖 |
| `MAP_TILE_SUBDOMAINS` | | `1234` | 瓦片子域 |
| `MAP_TILE_COORD` | | `gcj02` | 底图坐标系；OSM 请改为 `wgs84` |
| `GEOCODE_PROVIDER` | | `amap` | `amap`（需 Key，国内更准）或 `osm`（免 Key）；设置页可覆盖 |
| `AMAP_KEY` | | 空 | 高德 Web 服务 Key；也可在设置页填写（加密存储） |
| `NOTIFY_WEBHOOK_URL` | | 空 | 通用 JSON webhook |
| `NOTIFY_PUSHPLUS_TOKEN` | | 空 | PushPlus |
| `NOTIFY_SERVERCHAN_KEY` | | 空 | Server 酱 |
| `NOTIFY_NTFY_URL` | | 空 | ntfy topic URL |
| `NOTIFY_EVENTS` | | verification_required,failed | 逗号分隔：`verification_required,failed,daily_summary` |
| `AI_BASE_URL` / `AI_API_KEY` / `AI_MODEL` | | 空 | OpenAI 兼容接口；不配置则只用模板 |
| `CORS_ORIGINS` | | 空 | 前后端分域部署时填写 |

> AI 与地图/地址服务支持两种配置方式：**设置页**（写入数据库，加密保存 Key，优先级更高）
> 和下面的环境变量（作为默认值/回退）。改完设置页立即生效，不需要重启。

## 2. Docker Compose

```bash
cp .env.example .env
# 修改 APP_SECRET / ADMIN_PASSWORD
docker compose up -d --build
docker compose logs -f backend
```

- 前端：<http://localhost:8080>
- 后端 API：<http://localhost:8000/api/health>
- 数据：`./data/gxy.db`（SQLite WAL）
- 模型：`./models/`（只读挂载）

升级：

```bash
git pull
docker compose up -d --build
```

数据库表由 SQLAlchemy `create_all` 创建，当前版本新增列由 `backend/app/db.py` 的幂等迁移处理。升级前仍需备份数据库与 APP_SECRET；迁移不替代完整的版本管理。

## 3. 本地开发

从仓库根目录运行，完整说明见 [README](../README.md#本地运行)。本地 `.env` 应使用 `DATABASE_URL=sqlite:///./data/gxy.db`，开发时建议 `SCHEDULER_ENABLED=false`。

```bash
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows PowerShell: .\\.venv\\Scripts\\Activate.ps1
python -m pip install -r backend/requirements.txt
python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000

# 另一个终端，从仓库根目录开始
cd frontend
npm ci
npm run dev                   # http://localhost:5173
```

前端 `vite.config.ts` 已把 `/api` 代理到 `127.0.0.1:8000`。

## 4. 首次使用

1. 登录管理台，进入 **账号管理 → 新增账号**。
2. 填手机号、密码；填完整打卡地址与经纬度（`address` 参与签名）。
3. 保存后点 **登录检测**：成功会显示计划名称与岗位。
4. 设置上班/下班时间、星期；需要无人值守时打开 **自动打卡**。
5. 需要报告时先在 **设置 → AI 写作** 填 Base URL / 模型 / Key 并测试连接。
6. 在 **实习报告** 填岗位与职责（账号编辑里的“AI 写作人设”），生成周/月大纲，
   再按天生成草稿，确认内容后提交。
7. 出现 **验证中心** 任务时，按页面提示完成本人验证并点「我已完成验证」。

## 5. 备份与恢复

```bash
# 停机备份（推荐）
docker compose stop backend
cp data/gxy.db data/gxy.db.bak-$(date +%Y%m%d)
docker compose start backend
```

WAL 模式下热拷贝可能不一致；若必须热备，使用 `sqlite3 data/gxy.db ".backup data/backup.db"`。

`APP_SECRET` 必须与数据库一并备份：丢失后账号密码和会话无法解密，只能重新录入。

## 6. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 登录检测失败：`登录失败` | 手机号/密码错误、滑块未通过、或账号被风控。查看执行日志的 code/msg |
| `需要本人完成安全验证` | 正常的 303/304；到验证中心完成官方验证后点“我已完成验证” |
| `请求已被接受，但考勤记录未确认` | 服务端没写入或查询时间窗未覆盖；先到记录页核对，**不要重复点打卡** |
| 点选验证码显示“需手动点选” | 未配置 ONNX 模型；直接在图片上按顺序点击字符即可 |
| 自动打卡没触发 | 检查 `SCHEDULER_ENABLED`、账号 `enabled` / `auto_clock_in`、星期与时间窗口（45 分钟） |
| 报告提交被拒绝 | 学校动态表单必填项未填、周期不对、或附件要求 |
| 401 / 登录已过期 | 重新登录管理台；工学云 token 过期会在执行时自动重新登录一次 |
| 容器时间不对 | 定时以 `APP_TIMEZONE_OFFSET=8`（北京时间）计算，与宿主机时区无关 |
| Linux 下 `unable to open database file` | bind mount 的 `./data` 属于 root，容器用户是 uid 10001；先执行 `sudo chown -R 10001:10001 data models`，或改用 Docker named volume |
| 点选验证码总是要手动 | 未放模型文件；把 `yolov5n.onnx`、`ocr.onnx` 放入 `models/` 并重启后端 |

## 7. 安全建议

- 不要把管理台直接暴露在公网；需要时放在 VPN / Zero Trust / 反向代理认证之后。
- 使用强 `ADMIN_PASSWORD`，首次登录后立即修改。
- 不要提交 `.env`、`data/`、任何日志到公开仓库。
- 通知渠道会收到打卡结果摘要（不含 token），请确认接收方可信。
- 使用 AI 生成报告时，正文 prompt 会包含实习计划/单位名称，请自行评估隐私。

## 8. 已知限制

- 只实现了学生/教师两条主打卡路径，未覆盖所有学校自定义规则；
- 补卡审批、附件上传、图片水印等未实现（模型字段保留，可按需扩展）；
- 未做多副本调度协调、限流与审计导出；
- 服务端字段容忍度、303 token 来源等仍是未知项，代码采取保守失败。


## 9. AI 与地图说明

- AI 只使用 OpenAI Chat Completions 形状的接口：`Base URL + /chat/completions`。
  常见配置：DeepSeek `https://api.deepseek.com/v1`、通义 `https://dashscope.aliyuncs.com/compatible-mode/v1`、
  OpenAI `https://api.openai.com/v1`。
- 未配置 AI 时功能不会失效：大纲与正文都会回退到模板，并在界面标明“模板”。
- 默认高德栅格模板的请求不带 Key；这不等于获得无限免费或商用授权。请遵守地图服务提供方条款。
  高德地址搜索/反查需要 Web 服务 Key，`GEOCODE_PROVIDER=amap`；申请 Key 不自动赋予全部用途的许可。
- 地址反查依赖外网；不可用时仍可点选地图得到经纬度，手动填写地址即可。
