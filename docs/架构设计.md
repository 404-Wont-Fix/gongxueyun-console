# 架构设计

## 1. 目标

一个自托管、可审计的工学云实习助手：

- 多账号托管，管理员可创建子账号；
- 按时间自动上班 / 下班 / 休息打卡，跟随官方放假与调休，遇验证暂停并通知；
- 日报 / 周报 / 月报草稿、提交与回查；
- 管理台卡片式界面，按钮语义明确；
- **只有服务端记录确认的打卡才算成功**。

非目标：绕过人脸/实名验证、伪造定位、绕过学校规则。

## 3. 数据模型

| 表 | 关键字段 | 说明 |
|---|---|---|
| `users` | username, password_hash(scrypt), role | 管理台账号；admin 可看所有托管账号 |
| `accounts` | phone, password_enc, device, location, coord_type, profile, 时间/星期, 报告设置, plan, session_enc | 一个工学云账号 |
| `executions` | kind, subtype, status, message, detail, target_date, guard_key | 所有操作日志 |
| `verification_sessions` | payload_enc, register_url_enc, out_register_no_enc, state, resume_attempted | 暂停的打卡 |
| `report_drafts` | report_type, title, content, period, form_fields, plan_id, plan_date, status | 报告草稿 |
| `report_plans` | kind, start/end, items[], source, status | AI/模板写作大纲 |
| `app_settings` | key, value | AI、地图等全局设置 |
| `calendar_years` | year, days, sources, accepted_at | 三源核对后的年度日历与同步状态 |
| `calendar_overrides` | account_id, day, mode | 单账号单日排班覆盖 |
| `attendance_months` | account_id, month, records | 主动同步的远端考勤快照 |

- `password_enc` / `session_enc` / `payload_enc` 使用 Fernet（key = SHA-256(`APP_SECRET`)），
  接口任何响应都不包含这些字段。
- `executions.guard_key = "{account_id}:{date}:{kind}"` 上有唯一索引：同一账号同一天同一
  类型只允许一条“已确认”记录，防止并发/重试造成重复成功计数。
- `accounts.locked_until + lock_owner` 是简易 CAS 锁：同一账号同一时刻只跑一个写任务。

## 4. 打卡状态机

```
                    ┌─────────────── code != 200 ──────────────> rejected
                    │
submit ──> 200 ─────┼── msg 302 ──> 自动识别 ──> 重试一次 ──┐
                    │      └────── 识别不可用/失败 ──> captcha_required（验证中心手动点选）
                    ├── msg 303 ──> verification_required(face)
                    ├── msg 304 ──> createAxdjk ──> verification_required(account)
                    └── 其他 ──> listSynchro 回查 ──┬── 命中 ──> success
                                                   └── 未命中 ─> submitted_unconfirmed
```

- 写请求**不做盲目重试**；只有以下两类会重发：
  1. 服务器明确返回“token 失效”（说明写入被拒绝），重新登录后重发一次；
  2. 服务器要求 302 验证码或本人验证，完成后再提交一次。
- 超时/网络异常一律返回未知结果，并提示先查记录。

## 5. 验证会话

```
captcha_required ──点击坐标──> check + save ──> success / verification_required / 换一张
awaiting_verification(304)
  ├─ 手动/自动 queryAxdj（200 且 data 为 null/true）
  ├─ 先回查记录（可能用户已在官方 APP 完成，记录已存在）
  ├─ UPDATE ... SET resume_attempted=1 WHERE resume_attempted=0   ← 先落库占位
  ├─ 携带 outRegisterNo（+ attendanceId）重发一次
  └─ 回查记录 → record_confirmed / submitted_unconfirmed
```

- `resume_attempted` 是数据库层的“一次性”标记：即使进程崩溃，也不会第二次发送。
- `queryAxdj` 成功只代表“验证被确认”，不代表考勤存在；两者分开判断。
- 部分本人验证分支有记录查询失败保护；验证码续提及各学校的验证语义仍需真实环境核验，不应把这些机制当作完整幂等保证。

## 6. 调度

- APScheduler 在 backend 进程内运行（`SCHEDULER_ENABLED=true`）。
- 每 `SCHEDULER_TICK_SECONDS` 检查一次：
  - 按单日覆盖、官方日历、普通执行星期决定 START/END 或 HOLIDAY，判断是否到点（45 分钟窗口）；
  - 是否已有进行中/已完成的执行（避免重复提交）；
  - 是否有未关闭的验证会话（有则跳过，避免叠加）；
  - 账号任务随机延迟 0–90 秒，避免整点尖峰。
- 报告任务按 `report_time` 触发，先查远端是否已提交，再生成草稿并提交。
- 验证轮询：每 8 秒以上检查一次未结束的 304 会话，验证确认后自动续提。

> 多副本部署时只让一个副本开启调度器：数据库锁能防重复写入，但重复的验证码请求会浪费额度。

## 7. 前端

- Vue 3 + Vite + Pinia + Vue Router，无重型 UI 框架，使用自定义设计系统（`src/styles/main.css`）。
- 卡片式布局：总览统计卡、账号卡、验证卡、草稿卡；表格用于记录与日志。
- 移动端侧边栏抽屉、卡片单列；表单在两列布局下自适应。
- 所有危险操作都需要二次确认（删除账号）或明确的动作按钮（续提、取消）。
- 验证码图片按原始像素换算坐标，显示已点击的序号。

## 8. 安全边界

| 项 | 措施 |
|---|---|
| 密码 | scrypt（N=2^14, r=8, p=1），不存明文 |
| 账号密码 / 会话 | Fernet 加密；`APP_SECRET` 变更后旧数据不可解密（需重新登录） |
| 登录态 | HS256 JWT，7 天过期；前端只放 localStorage，401 自动登出 |
| 越权 | 所有 account 路由校验 `owner_id`（admin 例外） |
| 日志 | 只记录 code/msg/marker/状态，不记录 token、密文、登记号 |
| 验证链接 | `registerUrl` 加密存储，接口只返回链接本身；登记号不回传 |
| 盲写 | 签名缺字段直接拒绝；写请求不重试；续提一次性 |

## 9. 与参考项目的取舍

**保留**：27xk / tangqingfeng7 的字段集与签名顺序、Huee 的周期计算、kaka-niu 的
`appUuid` 复用、tangqingfeng7 的记录回查与“不确定性不重发”思路。

**去掉**：把 `code==200` 当成功、304 用点选绕过、盲填表单、写请求自动重试、
明文密码、日志含 token、303 中文提示拼链接、用固定旧版本号冒充“已适配”。

详见 [协议实现说明](协议实现说明.md)。


## 10. AI 写作与写作计划

```
人设（岗位/职责/工具） ─┐
                        ├─> 生成周/月大纲（AI 或模板兜底）
周期说明/补充要点 ─────┘        │
                                ▼
                      report_plans.items[]（每天 theme/tasks/要点）
                                │
        生成报告时读取当天/本期计划 ─┴─> AI 写正文 ─> 草稿 ─> 你确认 ─> 提交 ─> 回查
```

- AI 配置可在 **设置 → AI 写作** 中维护（Key 加密存入 `app_settings`），也可用环境变量。
- 大纲覆盖账号设置的“执行星期”，只排工作日。
- AI 失败会自动回退到模板大纲/模板正文，并在 UI 标明来源（`source=ai|template`）。
- Prompt 明确要求不编造数据、客户名称和奖励；正文仍是草稿，需要本人校对后提交。

## 11. 地图与坐标系

- 前端 Leaflet + 可配置瓦片；默认高德栅格瓦片（GCJ-02，国内可访问），可通过
  `MAP_TILE_URL` / `MAP_TILE_SUBDOMAINS` / `MAP_TILE_COORD` 换成 OSM 等。
- 账号保存 `coord_type`（默认 `gcj02`）。地图点选时按“底图坐标系 → 账号坐标系”换算，
  不做隐式转换；GCJ-02 ↔ WGS-84 的实现同时存在于前端（即时显示）和后端（测试覆盖）。
- 地址搜索/反查通过后端代理（Nominatim 或高德），避免浏览器 CORS 与 Key 泄漏；
  反查不可用时保留坐标并提示手动填写地址。
